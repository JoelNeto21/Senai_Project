═══════════════════════════════════════════════════════════════════════
## REGRAS DE NEGÓCIO IMPLEMENTADAS
═══════════════════════════════════════════════════════════════════════

✅ 1. Saída bloqueada se quantidade > saldo disponível
   - Retorna HTTP 422 com mensagem de erro clara

✅ 2. Toda saída exige campo 'justification' não nulo
   - Validação implementada em StoreMovementRequest
   - Campo é obrigatório se type='saida'

✅ 3. Apenas usuários autenticados alteram estoque
   - Middleware 'auth:sanctum' protege todas as rotas da API
   - User ID é automaticamente capturado de Auth::id()

✅ 4. Transação atômica para movimentos
   - Atualização de quantidade e criação de registro acontecem juntas
   - Se falhar a criação do registro, a quantidade NÃO é alterada

✅ 5. Nível crítico < 10 unidades
   - Método isCriticalStock() no modelo Book
   - Campo is_critical_stock retornado na resposta

✅ 6. Estoque não pode ficar negativo
   - Quantidade mínima é 0 nas validações
   - Decrement nunca deixa quantidade negativa (job)

## TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════

P: "Class not found" para BookResource?
R: Execute: php setup_api.php

P: "Token invalid" ao usar a API?
R: Certifique-se de:
   1. Sanctum está instalado (php artisan sanctum:install)
   2. User model tem trait HasApiTokens
   3. O token é válido e não expirou

P: Movimento não registra corretamente?
R: Verifique:
   1. User está autenticado (middleware auth:sanctum)
   2. Book ID existe
   3. Para saida: justification está preenchido

P: Erro 422 ao criar livro?
R: Verifique:
   1. title não está vazio
   2. isbn é único
   3. subject não está vazio
   4. quantity é um número inteiro >= 0
